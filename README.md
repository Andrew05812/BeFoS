## About

BeFoS отвечает на вопрос «почему именно эти два процента», а не только показывает число. Движок
детерминирован и версионирован: одинаковый вход даёт одинаковый выход, и результат можно воспроизвести
по сохранённым ответам. Там, где сравнивать не с чем, полоса категории помечена как «нет данных», а не
как измеренные пятьдесят процентов.

Работает весь путь: регистрация → анкета → тест → подбор → взаимный матч → чат → разбор совместимости
и карта пары → идея совместной активности → согласованный час. Заглушек в этом потоке нет — ни случайных
процентов, ни фейковых профилей за интерфейсом, ни имитации realtime-канала.

## Возможности

**Разбор совместимости.** Семь взвешенных категорий: ценности, личность, интересы, общение, уклад,
досуг, цели знакомства. Кроме общего процента API отдаёт точки совпадения, названные расхождения и
общие интересы — всё вычислено из двух профилей, ничего не сгенерировано.

**Анкета и тест.** 21 вопрос в пяти категориях; две оставшиеся оси сравнения — интересы и цели
знакомства — читаются из анкеты. Тест идёт по категориям, продолжается с того места, где его бросили, а
часть вопросов задаётся шкалой. Незаполненный раздел анкеты назван и ведёт в него.

**Подбор.** Кандидаты берутся из хранимой ранжированной колоды и читаются курсором, поэтому страницы не
съезжают, пока пул меняется. На карточке лежит объяснение, выведенное из двух профилей, а не из шаблона.

**Чат и карта пары.** Сообщения уходят по REST и рассылаются в WebSocket пары; повтор отправки
переиспользует ключ идемпотентности, прочтение считается квитанцией, а переподключение дозагружает
пропущенный разрыв. Compatibility Universe носит тот же разбор по узлам и отвечает, насколько уверенным
является каждый из них.

**Идеи для встречи.** Каталог из 25 активностей оценивается под оба профиля и их город; выбор виден
рядом с выбором партнёра, отклонённая идея не возвращается на свою страницу, согласованный час входит в
переписку карточкой, а час, который прошёл, назван прошедшим.

**Отказ, который что-то делает.** Блокировка удаляет пару и её историю на сервере в обе стороны и
перепроверяется на каждом кадре сокета. Это не фильтр ленты.

## Технологии

- **Клиент** — Kotlin 2.2, Jetpack Compose (Material 3), Navigation Compose, Ktor (HTTP + WebSocket),
  Coil, DataStore, Coroutines/Flow; разбиение `core / data / domain / presentation`.
- **Сервер** — Python 3.12, FastAPI, Pydantic 2, SQLAlchemy 2.0 (async), asyncpg, Alembic; один
  асинхронный процесс, без очереди, кэш-слоя и микросервисов.
- **Данные** — PostgreSQL 16 (22 таблицы), загрузки в `/uploads` с перенкодированием Pillow на приёме.
- **Защита** — JWT с ротируемым refresh, bcrypt, скользящий rate limiting, авторизация на уровне
  объекта с отказом `404`, проверка production-конфигурации на старте.
- **Сборка и проверки** — Docker Compose, GitHub Actions (пять job'ов плюс фильтр CodeQL), pytest,
  JUnit4 + MockK и живой продуктовый путь двумя аккаунтами.

## Запуск

```bash
cp .env.example .env
docker compose up --build
```

Compose поднимает PostgreSQL и бэкенд, применяет миграции, засевает каталоги и демо-данные и отдаёт API
на `http://localhost:8000`; интерактивная документация — `/docs`. Клиент:

```bash
cd android && ./gradlew :app:assembleDebug
```

Репозиторий клонируют **без `--depth`**: из shallow-клона граф задач Gradle не разрешается. Эмулятор
достаёт до хоста через `10.0.2.2`, поэтому бэкенд на `localhost:8000` не требует дополнительной
конфигурации. Демо-доступ при `DEMO_ENABLED=true` (значение по умолчанию): `demo@befos.app` /
`Demo12345`.

Без Docker, тесты, релизная сборка и разбор задержек — в
[`docs/OPERATIONS.md`](docs/OPERATIONS.md) и [`docs/VERIFICATION.md`](docs/VERIFICATION.md).

## Чего в проекте нет

Сказано прямо, чтобы страница не обещала лишнего: боевого развёрнутого окружения нет (сервис работает
локально или в Docker Compose на одном хосте); push-уведомлений нет — реализация требует ключ сервиса
Firebase Cloud Messaging, а своего проектного ключа в репозитории нет и придумать его нельзя; панели
модерации жалоб нет, они читаются через SQL; загрузка своего снимка работает на сервере, но ни один
экран клиента её не вызывает.
